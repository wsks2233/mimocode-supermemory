### [6] Context injection uses three synthetic chat.message part mutations, all marked `synthetic: true` so capture later excludes them: (1) optional keyword-trigger nudge pushing `MEMORY_NUDGE_MESSAGE` that orders the agent to call `supermemory` with `mode:"add"`; (2) every-turn reasoned-recall directive via `output.parts.push(recallPart)`; (3) first-message-only `[SUPERMEMORY]` memory block via `output.parts.unshift(contextPart)`, gated by an in-memory `injectedSessions` Set.

### [9] Reasoned-recall is a model-gated retrieval pattern: every user message receives a synthetic `<supermemory-recall>` directive that instructs the agent to silently decide whether recalling saved memory would materially improve THIS answer, then call `supermemory` with `mode:"search"` only when earlier work/conventions/preferences are likely relevant; trivial messages skip. `permission.ask` auto-allows when the permission payload's tool/mode is supermemory+search (`isSupermemoryRecallSearch`), so recall is zero-friction. Debug mode `SUPERMEMORY_DEBUG=1` appends a `[recall-decision] yes|no` instruction.
- quote: "export const DEFAULT_RECALL_DIRECTIVE = `<supermemory-recall>\\nBefore responding, silently decide whether recalling saved memory ... would materially improve your answer to THIS message. ... Recall — by calling the \\`supermemory\\` tool with \\`mode: \"search\"\\` — when the message:\\n- refers to earlier work or decisions ... Skip recall when the message is self-contained, trivial, a greeting/meta...\\n</supermemory-recall>`; ... \"permission.ask\": async (input, output) => { if (isSupermemoryRecallSearch(input)) { output.status = \"allow\"; } }"
- url: https://api.github.com/repos/supermemoryai/opencode-supermemory/contents/src/services/recall.ts + src/index.ts + https://www.npmjs.com/package/opencode-supermemory

### [10] Automatic capture lifecycle rides the `event` hook: `message.updated` marks sessions active; `session.idle` refreshes a turn snapshot from `client.session.messages` and flushes cadence batches every `captureEveryNTurns` completed turns (default 3); `session.deleted` flushes remainder; `server.instance.disposed` flushes all active sessions. Batches are idempotent via capture ID `opencode:capture:{sha256(sessionID:firstTurn:lastTurn)}` stored in a Set. Text extraction drops `synthetic`/`ignored` parts, strips `<private>` tags, skips fully-private turns, and only keeps final assistant messages (`role==="assistant" && typeof finish==="string" && finish!=="tool-calls"`). Writes go through `memoryClient.ingestConversation` with metadata `sm_scope:"personal"`, `sm_capture_mode:"automatic"`, `captureReason:"cadence"|"session_end"`, session/turn ranges.
- quote: "if (event.type === \"session.idle\") { ... await captureCadence(sessionID, turns); } if (event.type === \"session.deleted\") { ... await captureSessionEnd(sessionID); } if (event.type === \"server.instance.disposed\") { await Promise.all([...activeSessions].map(...captureSessionEnd...)); } ... function getCaptureId(sessionID, batch) { ... return `opencode:capture:${digest}`; } ... sm_capture_mode: \"automatic\", captureReason: reason"
- url: https://api.github.com/repos/supermemoryai/opencode-supermemory/contents/src/services/capture.ts
- source_type: primary
- published: 2026-09-17
- confidence: high

### [11] Preemptive compaction is implemented outside OpenCode's `experimental.session.compacting` hook: the plugin's `event` handler watches finished assistant `message.updated` payloads, computes `(tokens.input + tokens.cache.read + tokens.output) / contextLimit` against `compactionThreshold` (default 0.80), with guards `MIN_TOKENS_FOR_COMPACTION=50_000`, `COMPACTION_COOLDOWN_MS=30_000`, `DEFAULT_CONTEXT_LIMIT=200_000`; model limits come from a one-shot `client.provider.list()` cache (fallback 200k). When triggered it (1) fetches project memories, (2) writes a synthetic user hook message into OpenCode's on-disk store at `~/.opencode/messages/{sessionID}/` + `~/.opencode/parts/{messageID}/` containing a `[COMPACTION CONTEXT INJECTION]` prompt (sections: User Requests / Final Goal / Work Completed / Remaining Tasks / MUST NOT Do / Project Knowledge), (3) calls `client.session.summarize()`, (4) after summary-message finish, saves `[Session Summary]\\n{content}` as a Supermemory entry typed `conversation` with `sm_capture_mode:"compaction"`, then optionally auto-prompts "Continue" via `client.session.promptAsync`.
- quote: "const DEFAULT_THRESHOLD = 0.80; const MIN_TOKENS_FOR_COMPACTION = 50_000; const COMPACTION_COOLDOWN_MS = 30_000; const DEFAULT_CONTEXT_LIMIT = 200_000; ... const MESSAGE_STORAGE = join(homedir(), \".opencode\", \"messages\"); const PART_STORAGE = join(homedir(), \".opencode\", \"parts\"); ... const totalUsed = tokens.input + tokens.cache.read + tokens.output; ... if (usageRatio < threshold) return; ... await ctx.client.session.summarize({ path: { id: sessionID }, body: { providerID, modelID }, ...}); ... type: \"conversation\", sm_capture_mode: \"compaction\""
- url: https://api.github.com/repos/supermemoryai/opencode-supermemory/contents/src/services/compaction.ts + https://www.npmjs.com/package/opencode-supermemory
- source_type: primary
- published: 2026-09
- confidence: high

### [12] Memory scoping is unified across coding agents via a shared Supermemory container tag `repo_{project-name}__{hash(normalized Git origin remote)}` (fallback: hash of real filesystem path when no origin); user vs project memories are distinguished by metadata `sm_scope: "personal"|"project"` inside the same container. OpenCode still reads legacy containers (`user_project_*`, `claudecode_project_*`, `codex_*`, `opencode_*`) so upgrades need no migration. npm README states OpenCode sends the same shared coding-agent entity context as Claude Code and Codex.
- quote: "Repository tag: `repo_{project-name}__{hash(normalized-origin-remote)}` ... Personal and project memories are distinguished with `sm_scope` metadata inside the shared repository container. ... The repository hash comes from the normalized Git `origin` remote, so Claude Code, Codex, and OpenCode use the same container for the same repository."

### [13] Copyable wiring pattern for a near-native MiMoCode plugin layer: (1) host loads plugins from a config string-array + local plugin dirs, passes an SDK client + cwd/worktree into an async Plugin factory; (2) plugin returns hooks for chat-message mutation, permission policy, lifecycle events, and a custom tool map; (3) agent-visible context = first-turn memory block + every-turn reasoned-recall directive + explicit multi-mode tool; (4) silent write path = keyword detection + batched idempotent turn capture on idle/delete/shutdown + compaction-time summary save; (5) privacy = synthetic parts excluded from capture + `<private>` redaction; (6) install UX = dedicated CLI that writes plugin name into host config and creates slash commands under `~/.config/opencode/commands/` (commit e898295, 2026-09-17: "OpenCode docs discover ~/.config/opencode/commands/; the singular command/ directory is legacy"). Supermemory also documents self-host via `npx supermemory local` + `baseUrl` override in `~/.config/opencode/supermemory.jsonc`.
- quote: "bunx opencode-supermemory@latest install --no-tui ... Register the plugin in `~/.config/opencode/opencode.jsonc` ... Create the `/supermemory-init` command ... { \"plugin\": [\"opencode-supermemory\"] } ... This plugin works with self-hosted Supermemory — run `npx supermemory local`, then set apiKey / base URL ... Write commands to commands/ and bump to 2.0.14 — OpenCode docs discover ~/.config/opencode/commands/"
- url: https://www.npmjs.com/package/opencode-supermemory + https://supermemory.ai/docs/integrations/opencode + https://api.github.com/repos/supermemoryai/opencode-supermemory/commits
- source_type: primary
- published: 2026-08 to 2026-09-17
- confidence: high

### [14] OpenCode custom tools (the injection vehicle Supermemory uses) are created with `tool({ description, args: zodSchema, execute })` from `@opencode-ai/plugin`; they sit alongside built-in tools and a plugin tool with the same name as a built-in takes precedence. Plugins can also mutate tool args via `tool.execute.before` (example: bash arg escaping) and inject env via `shell.env`.
- quote: "Plugins can also add custom tools to opencode: ... import { type Plugin, tool } from \"@opencode-ai/plugin\" ... If a plugin tool uses the same name as a built-in tool, the plugin tool takes precedence. ... \"tool.execute.before\": async (input, output) => { if (input.tool === \"bash\") { output.args.command = escape(output.args.command) } }"
- url: https://opencode.ai/docs/plugins/
- source_type: primary
- published: 2026-09-18
- confidence: high
