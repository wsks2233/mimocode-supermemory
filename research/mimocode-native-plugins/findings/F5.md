# F5: Agent 记忆层横向对比：supermemory vs mem0 / Letta(MemGPT) / Zep / cognee，以及它们如何挂接到 coding agent

## Findings

### [1] Supermemory 官方将自身定位为 “Context infrastructure for AI agents”，对外暴露三条主路径：开发者 API/SDK、Plugins and MCP（“Drop memory into Claude and coding agents”）、以及 self-hosting。
- quote: "Context infrastructure for AI agents. Use it with the API, your tools, your team, or run it yourself." / "Plugins and MCP — Drop memory into Claude and coding agents"
- url: https://supermemory.ai/docs/
- source_type: primary
- published: unknown
- confidence: high

### [2] Supermemory 核心架构是「自研 learning model + 内部 temporal vector-graph engine」两件套：learning model 决定学什么/何时遗忘/如何建关系；graph engine 是 fact-based temporal graph，内建 Vector + FTS + graph 三路检索。
- quote: "At it's core, supermemory is powered by a custom learning model and a graph database that we built internally." / "Temporal Vector-graph engine — Where the learnings are actually stored, optimized for search. Fact-based temporal graph that has Vector, FTS, and graph built in."
- url: https://supermemory.ai/docs/concepts/how-it-works
- source_type: primary
- published: unknown
- confidence: high

### [3] Supermemory 摄入管线与产物是三分离的：document 经 queued→extracting→chunking→embedding→indexing→done；`done` 只表示 chunk 可检索，graph memories 来自第二阶段 “dreaming”；最终同一 containerTag 下产出 document chunks（RAG grounding）、memories（graph facts）、profile（always-on context）三类输出。
- quote: "Document status done means chunks are indexed for search. Memories — the graph facts, updates, and derives — come from a second phase called dreaming." / "After the pipeline runs, the same document leads to three things -> Chunks, Memories and Profile."
- url: https://supermemory.ai/docs/concepts/how-it-works
- source_type: primary
- published: unknown
- confidence: high

### [4] Supermemory 的 coding-agent 插件 `opencode-supermemory` 用统一 repository container 打通多 agent：container tag 形如 `repo_{project-name}__{hash(normalized Git origin remote)}`，Claude Code / Codex / OpenCode 对同一 repo 写入同一容器，人/项目记忆用 `sm_scope` 元数据（`personal`|`project`）区分；无 origin 时回退 hash(真实文件系统路径)。
- quote: "OpenCode sends the same shared coding-agent entity context as Claude Code and Codex. Personal and project memories are distinguished with sm_scope metadata inside the shared repository container." / "The repository hash comes from the normalized Git origin remote, so Claude Code, Codex, and OpenCode use the same container for the same repository."
- url: https://raw.githubusercontent.com/supermemoryai/opencode-supermemory/main/README.md
- source_type: primary
- published: unknown
- confidence: high

### [5] `opencode-supermemory` 在 coding agent 内的挂接形态是「OpenCode native plugin」而非仅 MCP：注册进 `~/.config/opencode/opencode.jsonc` 的 `plugin` 数组；行为包括首条消息注入 profile/project/user memories、每回合 “reasoned recall”（agent 自主决定是否调用 supermemory tool 搜索）、自动 capture（`captureEveryNTurns`）、关键词触发保存、`/supermemory-index` 代码库索引、以及 80% context 时 preemptive compaction（把 project memories 注入 summarization 并把 session summary 存回记忆）。
- quote: "On first message, the agent receives (invisible to user): Personal profile for the current project, Project memories, Relevant user memories (semantic search)." / "When context hits 80% capacity: 1. Triggers OpenCode's summarization 2. Injects project memories into summary context 3. Saves session summary as a memory."
- url: https://raw.githubusercontent.com/supermemoryai/opencode-supermemory/main/README.md
- source_type: primary
- published: unknown
- confidence: high

### [6] Supermemory 官方 MCP 是 remote HTTP server（`https://mcp.supermemory.ai/mcp`），OAuth 登录、无需 API key；工具集覆盖 search_memory / get_profile / add_memory(save|forget) / list_documents / get_document / list_memories / list_spaces / who_am_i；支持 MCP Apps 的客户端可渲染 select-space、guided-save、upload-file、memory-graph 四个交互 widget；isolation 以 space + containerTag 为硬边界。
- quote: "Add this remote MCP server to any compatible client: https://mcp.supermemory.ai/mcp" / "Supermemory uses OAuth, so no API key is required." / "Clients that support MCP Apps can open these Supermemory widgets directly inside the conversation."
- url: https://supermemory.ai/docs/supermemory-mcp/mcp
- source_type: primary
- published: unknown
- confidence: high

### [7] Mem0 的记忆架构是「应用侧 add/search API + 服务端三存储」：写入时 LLM 抽取事实（默认 ADD-only 聚合式，不重写旧记忆）、去重嵌入、实体抽取；事实与元数据进 SQL，embedding 进 vector store，实体进 entity store；Platform 上 entity store 进一步支撑 Graph Memory，OSS 无 graph 只有 entity overlap boost。
- quote: "Mem0 sits between your application and your model. You send conversation turns to add, then call search before the next model request to fetch relevant context." / "The automatic extraction path is additive. If a user says, 'I moved from Austin to Seattle,' Mem0 can store the new fact without silently rewriting the old one."
- url: https://docs.mem0.ai/core-concepts/how-it-works
- source_type: primary
- published: unknown
- confidence: high

### [8] Mem0 检索是多信号融合：semantic（向量）、keyword（字面）、entity（实体 boost）、temporal（写入时提取的时间元数据 vs 查询时间意图）；Platform 由托管服务融合，OSS 依赖所配 vector store + 可选 reranker。实体范围用 `user_id` / `agent_id` / `app_id` / `run_id` + metadata 过滤。
- quote: "Platform retrieval fuses these signals in the managed service, where the entity signal is powered by built-in Graph Memory. OSS retrieval depends on your configured vector store and optional reranker, and boosts on entity overlap alone: it has no graph memory."
- url: https://docs.mem0.ai/core-concepts/how-it-works
- source_type: primary
- published: unknown
- confidence: high

### [9] Mem0 同时提供 hosted MCP 与 native coding-agent plugin 两层挂接：MCP 端点 `https://mcp.mem0.ai/mcp`（可用 `npx mcp-add` 写入 Claude Code/Cursor/Windsurf/VS Code/OpenCode/Codex 等客户端配置），暴露 add_memory / search_memories / update_memory / delete_* 等 11 个工具；对 Codex 还支持从 mem0 monorepo sideload 完整 plugin（含 lifecycle hooks），并明确警告勿与手动 `[mcp_servers.mem0]` 重复注册。
- quote: "npx mcp-add --name mem0-mcp --type http --url \"https://mcp.mem0.ai/mcp\" --clients \"claude code,cursor,windsurf,vscode,opencode\"" / "If you want the memory protocol skill, Mem0 SDK skill, and opt-in lifecycle hooks alongside the MCP server, sideload the plugin from a clone of mem0ai/mem0."
- url: https://docs.mem0.ai/platform/mem0-mcp
- source_type: primary
- published: unknown
- confidence: high

### [10] Mem0 Claude Code 官方插件 v0.3.1 的可复用生命周期是「本地 capture → 后台 extract → 下一会话 auto-recall」：hooks 只在本机记 evidence（用户消息、Claude 回答、变更文件、测试/构建结果），每 5 次 completed exchange 或 idle 5 分钟由 detached background worker 调 Mem0 `add`；下一 session 首条 prompt ≥20 字符时自动 search 并注入最多 5 条记忆；显式工具只保留单一 `search_memories`（v0.2 的 9 个读写 MCP 工具被砍掉）。
- quote: "Capture happens in the background as you work. Hooks save user messages, Claude's answers, changed files, and test/build results locally. Capture records evidence locally; memory extraction runs through Mem0 in a background worker." / "Recall happens automatically before Claude's first response in a new session. If the first prompt has at least 20 characters, the plugin searches with that prompt and injects up to five relevant memories."
- url: https://docs.mem0.ai/integrations/claude-code
- source_type: primary
- published: unknown (plugin version 0.3.1)
- confidence: high

### [11] Mem0 Claude Code 插件的记忆作用域模型是「project 共享 + personal 私有」双桶：shared project memory 以 `agent_id`（项目身份，Git remote hash）为键、`app_id`（仓库）为 scope，不含 `user_id`；personal memory 以 `user_id` 为键、`app_id` 为 scope；search 返回两者并集，scope 可收窄为 `repo`（默认）/`dir`（层级向下可见）/`mine`；`run_id` 标记 coding-agent session，可选过滤。
- quote: "Shared project memory (keyed by agent_id, scoped by app_id): one namespace per repository... Project memory never carries a user_id, so teammates' searches never mix in your preferences." / "Personal memory (keyed by user_id, scoped by app_id): your preferred tools, style, habits..."
- url: https://docs.mem0.ai/integrations/claude-code
- source_type: primary
- published: unknown (plugin version 0.3.1)
- confidence: high

### [12] Mem0 把 coding-agent 插件实现收敛到共享内核：`integrations/agent-plugin-core/` 是 Python/TS 共享记忆行为的 single source，native plugins（Claude Code/Cursor/Codex/OpenCode/Kimi/Antigravity 等）各自薄壳；`integrations/mem0-agent-plugin/` 是 portable Agent Plugins v1 包（提供 search + skills 但不做 automatic capture）；另有 Claude Code Skill（`skills/mem0*`）与 marketplace manifest（`.agents/plugins/marketplace.json`）形态。
- quote: "The integrations/agent-plugin-core/ directory is the single source for shared Python and TypeScript memory behavior. Native plugins live in their own sibling directories, while integrations/mem0-agent-plugin/ is the single portable Agent Plugins v1 package."
- url: https://docs.mem0.ai/llms.txt
- source_type: primary
- published: unknown
- confidence: high

### [13] Letta（原 MemGPT）的记忆形态与「外部 memory API」路线不同：V1 的 memory blocks 是常驻 context 的结构化 XML 段（label/description/value/limit，agent 用内置工具自编辑，可 read-only、可跨 agent 共享 attach）；Agent SDK（V2）升级为 MemFS——agent 记忆是 agent 自有 git repo，投影到工作机上，commit+push 后才成为记忆，`system/` 下文件每轮进 system prompt，其余只暴露 file tree 按需读取；另有 dreaming（step-count 或 compaction-event 触发后台 subagent 整理记忆）。
- quote: "Memory blocks are structured sections of the agent's context window that persist across all interactions. They are always visible - no retrieval needed." / "An agent's memory is part of its state, not a folder on a machine: it lives in a git repository owned by the agent, which MemFS projects onto whatever computer the agent is working on."
- url: https://docs.letta.com/v1-sdk/memory/memory-blocks/ ; https://docs.letta.com/agent-sdk/memory/
- source_type: primary
- published: unknown
- confidence: high

### [14] Letta 官方把 Agent SDK（V2）对标到 coding-agent harness 一族：对比表将 V2 “Most similar to” 写为 “Claude Agent SDK, Codex SDK, OpenCode SDK”；V1 独有 Python SDK 且 V1 将被弃用，V2 目前 TypeScript-only；V2 新增 MemFS/dreaming、skills、subagents、mods、Slack/Telegram channels、预置 bash toolsets，V1 侧 server-side tools 在 V2 中基本消失（除 web search）。
- quote: "The Letta V1 SDK is being deprecated in favor of the Letta Agent SDK" / "Most similar to: Claude Agent SDK, Codex SDK, OpenCode SDK"
- url: https://docs.letta.com/v1-sdk/
- source_type: primary
- published: unknown
- confidence: high

### [15] Zep 的记忆单元是 Context Graph：基于开源 temporal graph 库 Graphiti 的时序知识图；节点为 entity，边承载 fact/relationship，edge timestamp 记录 fact 何时 valid/invalid；数据三类存储为 entity edges、entity nodes、episodic nodes；检索产物包括 facts/entities/episodes/thread summaries/observations/user summary 等 context types，并可组装成 Context Block；隔离模型是 user graph + thread + document/graph.add。
- quote: "Zep's Context Graph is the unit of agent memory. Nodes are entities, and edges are facts or relationships. The graph updates as new data arrives." / "The Context Graph Engine uses Graphiti, Zep's open-source temporal graph library."
- url: https://help.getzep.com/concepts ; https://help.getzep.com/graph-overview
- source_type: primary
- published: unknown
- confidence: high

### [16] Zep 挂接到 coding agent 的官方路径是 “Build with Zep” plugin（仓库 getzep/building-with-zep-plugin），一套同时装 Claude Code / Codex / Cursor：内含 `building-with-zep` skill（设计/摄取/检索/评估决策层）+ 远程文档 MCP `zep-docs`（`https://docs-mcp.getzep.com/mcp`，无需 API key）；文档另提示还有 “Zep Memory Plug-In” 给宿主注入登录用户自己的 agent memory，与 build plugin 可并存。形态是 skill + docs-MCP，而非把业务 memory 写接口直接做成 host plugin。
- quote: "The Build with Zep plugin gives Claude Code, Codex, and Cursor both: a skill that encodes how to design, build, and evaluate a Zep integration, and the Zep documentation MCP server for real-time search over the docs. One plugin installs in all three ecosystems." / "The Zep Memory Plug-In gives supported hosts the signed-in person's agent memory."
- url: https://help.getzep.com/implement-zep-with-agents
- source_type: primary
- published: unknown
- confidence: high

### [17] cognee 的存储是三系统互补：Relational store（文档/chunk/出处 provenance）、Vector store（语义相似度 embedding）、Graph store（entity+relationship 知识图）；处理模型是 DataPoints / Tasks / Pipelines 模块化组合；v1.0 用户侧主操作为 remember / recall / improve / forget（旧的 add / cognify / memify / search 降为底层 building blocks）；官方入口明确支持 “Python API or MCP server”。
- quote: "Cognee uses three complementary storage systems... Relational store — Tracks documents, chunks, and provenance... Vector store — Holds embeddings... Graph store — Captures entities and relationships in a knowledge graph." / "Main operations in Cognee v1.0 are remember, recall, improve, and forget"
- url: https://docs.cognee.ai/core-concepts/overview ; https://docs.cognee.ai/
- source_type: primary
- published: unknown
- confidence: high

### [18] 可复用架构形态（从上述一手材料归纳）：四家记忆层对 coding agent 的挂接收敛为三种叠加层——(A) 托管 REST/SDK API（应用/插件在 agent 外或 hook 内调用 add/search）；(B) 远程 HTTPS MCP（Supermemory `mcp.supermemory.ai` OAuth、Mem0 `mcp.mem0.ai` bearer/OAuth，工具集以 search/add/profile/list 为主）；(C) host-native plugin/skill（OpenCode `opencode.jsonc` plugin、Claude Code marketplace plugin、Codex plugin marketplace、Cursor Agents marketplace），负责 lifecycle capture、上下文注入、compaction 协同与作用域（containerTag / user_id+agent_id+app_id / git-backed MemFS）。差异在存储内核：Supermemory=temporal vector-graph + dreaming；Mem0=SQL+vector+entity(+Platform graph) ADD-only 蒸馏；Letta=agent 拥有的 core-memory blocks/MemFS git repo（记忆即 harness 状态）；Zep=temporal Context Graph（Graphiti）；cognee=relational+vector+graph 管线。
- quote: "Memory is what makes a Letta agent stateful. An agent's memory is its own: it persists across conversations, follows the agent between models and computers, and the agent edits it as it learns."
- url: https://docs.letta.com/agent-sdk/memory/ （归纳 claim，支撑材料见 [2][7][13][15][17]）
- source_type: primary
- published: unknown
- confidence: medium

## Dead ends
- WebSearch tool 在本环境不可用（三次不同措辞 query 均返回 “Web search unavailable”），无法做开放检索与交叉验证，改为按已知官方域名/文档路径直接 WebFetch 一手材料。
- `https://docs.supermemory.ai/introduction`、`https://github.com/supermemoryai/opencode-supermemory`、`https://github.com/topoteretes/cognee` 的 GitHub HTML 与部分 docs 子域返回 Transport error；改用 `https://supermemory.ai/docs/`、raw.githubusercontent README、`docs.cognee.ai` 成功获取。
- `https://help.getzep.com/_mcp/server` 返回的是 Zep 文档站自己的 fern-docs MCP 描述，不是产品 memory MCP 的工具清单；产品侧 coding-agent 挂接改以 `/implement-zep-with-agents` 为准。
- 未能取到 mem0/Zep/cognee/supermemory 的 arXiv 论文正文或正式 benchmark 数字（本 angle 未强依赖论文；Mem0 文档仅指向 memory-evaluation 页，未打开具体指标）。
