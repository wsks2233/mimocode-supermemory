# F6: 标准与协议：MCP / ACP / Agent Skills / OpenAI 工具模式——原生插件应绑定的公共标准与自研边界

## Findings

### [1] MCP 是连接 AI 应用与外部系统的开源协议标准，核心原语为 Tools / Resources / Prompts，传输为 JSON-RPC 2.0 + stdio 或 Streamable HTTP
- quote: "MCP (Model Context Protocol) is an open-source standard for connecting AI applications to external systems. ... Tools: Executable functions that AI applications can invoke to perform actions (e.g., file operations, API calls, database queries); Resources: Data sources that provide contextual information; Prompts: Reusable templates"
- url: https://modelcontextprotocol.io/docs/2026-07-28/learn/architecture
- source_type: primary
- published: 2026-07-28 (protocol revision; docs live as of research date)
- confidence: high

### [2] MCP 官方规范当前版本线为 2026-07-28（另有 2025-11-25 / 2025-06-18 / 2025-03-26 / 2024-11-05）；2026-07-28 起协议改为无状态：移除 initialize 握手，每请求携带 `_meta` 中的 protocolVersion 与 capabilities，新增强制 `server/discover`
- quote: "Make MCP stateless: remove the `initialize`/`notifications/initialized` handshake. Every request now carries its protocol version and client capabilities in `_meta` ... Add `server/discover`: servers MUST implement this RPC to advertise their supported protocol versions, capabilities, and identity."
- url: https://modelcontextprotocol.io/specification/2026-07-28/changelog
- source_type: primary
- published: 2026-07-28
- confidence: high

### [3] MCP 设计原则明确：协议只沉淀已被多实现验证的模式（Standardization over innovation）；能用现有原语组合的功能不进协议核心（Composability over specificity）；扩展（extensions）是试验场，规范才是收敛点
- quote: "We don't add protocol features for use cases that can be constructed from these existing building blocks. ... MCP standardizes patterns that have already proven valuable. ... Extensions are where convergence gets tested; the specification is where it gets committed."
- url: https://modelcontextprotocol.io/community/design-principles
- source_type: primary
- published: unknown (living doc; accessed 2026-09)
- confidence: high

### [4] MCP Tools 是 model-controlled 能力面：`tools/list` 发现 + `tools/call` 执行；安全要求宿主对工具调用保持 human-in-the-loop，且 tool annotations 在非可信 server 上视为 untrusted
- quote: "Tools in MCP are designed to be **model-controlled** ... there SHOULD always be a human in the loop with the ability to deny tool invocations. ... clients MUST consider tool annotations to be untrusted unless they come from trusted servers."
- url: https://modelcontextprotocol.io/specification/2025-06-18/server/tools
- source_type: primary
- published: 2025-06-18
- confidence: high

### [5] Agent Skills 是 Anthropic 发起并开源的跨 agent 能力扩展格式：目录含 `SKILL.md`（YAML frontmatter + Markdown）+ 可选 scripts/references/assets；通过 progressive disclosure（~100 token 元数据 → 激活时加载正文 → 按需加载资源）控制上下文成本；已被 Claude Code、Gemini CLI、Cursor、VS Code Copilot、OpenCode、Goose、ChatGPT/Codex 等大量客户端采用
- quote: "Agent Skills are a lightweight, open format for extending AI agent capabilities ... At its core, a skill is a folder containing a `SKILL.md` file. ... Discovery: At startup, agents load only the name and description of each available skill"
- url: https://agentskills.io/
- source_type: primary
- published: unknown (living standard; client showcase includes 2026-dated adopters)
- confidence: high

### [6] Agent Skills 开放规范字段边界：必填 `name`（≤64 字符，小写+数字+连字符，须与父目录名一致）与 `description`（≤1024）；可选 `license`/`compatibility`（≤500）/`metadata`/`allowed-tools`（实验性）；建议 SKILL.md <500 行、正文 <5000 tokens；校验工具为 `skills-ref validate`
- quote: "`name` | Yes | Max 64 characters. Lowercase letters, numbers, and hyphens only. ... `description` | Yes | Max 1024 characters. ... Keep your main `SKILL.md` under 500 lines."
- url: https://agentskills.io/specification
- source_type: primary
- published: unknown (living spec)
- confidence: high

### [7] Claude Code 自定义 commands 已合并进 skills：`.claude/commands/*.md` 与 `.claude/skills/<name>/SKILL.md` 均产生 `/name`；Claude Code 在 Agent Skills 开放标准之上叠加私有扩展（invocation control、subagent execution、dynamic context `!`cmd``、plugin namespacing `/plugin:skill`）
- quote: "**Custom commands have been merged into skills.** A file at `.claude/commands/deploy.md` and a skill at `.claude/skills/deploy/SKILL.md` both create `/deploy` and work the same way. ... Claude Code extends the standard with additional features like invocation control, subagent execution, and dynamic context injection."
- url: https://code.claude.com/docs/en/skills
- source_type: primary
- published: unknown (living docs; cites Claude Code v2.1.2xx behaviors, 2025–2026)
- confidence: high

### [8] Claude Code「插件」是宿主私有打包/分发层，而非新协议：`.claude-plugin/plugin.json` 清单 + skills/agents/hooks/.mcp.json/.lsp.json/monitors/bin；通过 marketplace（`claude-plugins-official` / `claude-community`）分发；插件技能命名空间为 `/plugin-name:skill-name` 以避免冲突
- quote: "Plugins let you extend Claude Code with custom functionality that can be shared across projects and teams. ... Plugin skills are always namespaced (like `/my-first-plugin:hello`) to prevent conflicts"
- url: https://code.claude.com/docs/en/plugins
- source_type: primary
- published: unknown (living docs; marketplace/CI details current as of 2026)
- confidence: high

### [9] MCP 官方 Skills 扩展（`io.modelcontextprotocol/skills`，SEP-2640 Final）把 Agent Skills 带上 MCP 总线：`skills/list` + `skills/get` 发现，内容仍走 `resources/read`；宿主必须校验 SHA-256 digest/size/frontmatter，审批绑定完整 manifest，单 skill 建议上限 512 files / 16 MiB；SDK/host 实现仍在推进中
- quote: "A skill is a directory containing a `SKILL.md` file ... following the Agent Skills specification. This extension defines discovery and retrieval over MCP. ... Servers SHOULD NOT exceed 512 files or 16 MiB per skill ... SDK and host support is still being implemented"
- url: https://modelcontextprotocol.io/extensions/skills/overview
- source_type: primary
- published: SEP-2640 Final (extension doc; protocol era 2026-07-28)
- confidence: high

### [10] Agent Client Protocol (ACP) 标准化的是「代码编辑器/IDE ↔ coding agent」会话与 UX 通道（JSON-RPC，本地 stdio / 远程 HTTP-WS），明确复用 MCP 的 JSON 类型与 MCP server 配置转发，而不是取代 MCP 做工具/上下文协议；方法面覆盖 initialize/authenticate/session/prompt、fs/terminal/permission/elicitation
- quote: "The Agent Client Protocol standardizes communication between code editors/IDEs and coding agents ... The protocol re-uses the JSON representations used in MCP where possible ... When forwarding the prompt from the user, it passes configuration for these to the agent. This allows the agent to connect directly to the MCP server."
- url: https://agentclientprotocol.com/overview/architecture
- source_type: primary
- published: unknown (living protocol v1; remote agents "work in progress")
- confidence: high

### [11] MCP 官方 Registry（preview）只托管公开 server 的元数据（`server.json`：反向 DNS 命名、包/远程 URL、安装说明），不做代码安全扫描、不支持私有 server；宿主应用应消费下游 marketplace/聚合器而非直连官方 Registry——自研插件市场边界应对标「下游聚合器」角色
- quote: "The MCP Registry is currently in preview. ... The MCP Registry does not support private servers. ... The MCP Registry is not intended to be directly consumed by host applications. Instead, host applications should consume other MCP registries, such as downstream marketplaces"
- url: https://modelcontextprotocol.io/registry/about
- source_type: primary
- published: unknown (preview status as of 2026-09)
- confidence: high

### [12] OpenAI 官方 Agents SDK 将 Tools 定义为 functions / MCP / hosted tools 三类，且明确依赖 MCP Python SDK；ChatGPT/Codex 亦被 agentskills.io 列为 Agent Skills 客户端——OpenAI 侧没有与 MCP 对立的私有插件总线，而是收敛到 MCP + Skills 双标准
- quote: "**Tools**: Various Tools let agents take actions (functions, MCP, hosted tools) ... Acknowledgements: ... MCP Python SDK"
- url: https://github.com/openai/openai-agents-python
- source_type: primary
- published: unknown (living README; retrieved 2026-09)
- confidence: medium
