# F4: 主流 coding agent 插件生态：MCP / Skills / Hooks / Plugins / Rules 与「接近原生」基线

## Findings

### [1] Claude Code plugins are self-contained packages bundling skills, agents, hooks, MCP servers, LSP servers, monitors, bin executables, and settings.json under a `.claude-plugin/plugin.json` manifest, with plugin skills namespaced as `/plugin-name:skill-name`.
- quote: "Plugins let you extend Claude Code with custom functionality that can be shared across projects and teams... with skills, agents, hooks, and MCP servers."
- url: https://code.claude.com/docs/en/plugins
- source_type: primary
- published: unknown (live docs as of 2026-09)
- confidence: high

### [2] Claude Code distributes plugins via two public marketplaces — curated `claude-plugins-official` (auto-registered on first interactive start) and community `claude-plugins-community` (nightly catalog sync; approved plugins pinned to a commit SHA) — plus private team marketplaces and `claude plugin eval` for measuring plugin contribution.
- quote: "Anthropic maintains two public marketplaces for Claude Code plugins: `claude-plugins-official`... and `claude-community`... Approved plugins are pinned to a specific commit SHA in the `anthropics/claude-plugins-community` catalog, and CI bumps the pin automatically."
- url: https://code.claude.com/docs/en/plugins
- source_type: primary
- published: unknown (live docs as of 2026-09)
- confidence: high

### [3] Claude Code hooks fire a deep lifecycle (SessionStart/End, UserPromptSubmit, PreToolUse, PostToolUse, PostToolBatch, SubagentStart/Stop, TaskCreated/Completed, Stop/StopFailure, PreCompact/PostCompact, PermissionRequest/Denied, Elicitation, FileChanged, ConfigChange, CwdChanged, etc.) and handlers can be shell commands, HTTP endpoints, MCP tool calls, LLM prompts, or multi-turn agent hooks, with matcher + optional `if` filters and decision control via JSON exit output.
- quote: "Hooks are user-defined shell commands, HTTP endpoints, MCP tool calls, LLM prompts, or subagents that execute automatically at specific points in Claude Code's lifecycle."
- url: https://code.claude.com/docs/en/hooks
- source_type: primary
- published: unknown (live docs as of 2026-09; debug samples reference 2026-07)
- confidence: high

### [4] Claude Code skills follow the Agent Skills open standard (agentskills.io) and load on demand; body cost is near-zero until invoked, locations span enterprise managed settings, personal `~/.claude/skills/`, project `.claude/skills/`, nested monorepo paths, plugins, and claude.ai account sync (~10 min poll, terminal sync requires v2.1.273+).
- quote: "Claude Code skills follow the Agent Skills open standard, which works across multiple AI tools... Unlike CLAUDE.md content, a skill's body loads only when it's used."
- url: https://code.claude.com/docs/en/skills
- source_type: primary
- published: unknown (live docs as of 2026-09)
- confidence: high

### [5] Agent Plugins 1.0.0 is an open, vendor-neutral package standard defining `plugin.json` + `skills/` (Agent Skills format) + `mcp.json` (stdio / Streamable HTTP / legacy HTTP+SSE) + reverse-domain client extension namespaces; its Technical Steering Committee includes Core Maintainers from Amazon, Cursor, Microsoft, OpenAI, and Vercel.
- quote: "Agent Plugins is an open, vendor-neutral standard for packaging reusable components into portable plugins. Its version 1.0.0 specification defines a shared format for Agent Skills and MCP servers... initial Technical Steering Committee includes Core Maintainers from Amazon, Cursor, Microsoft, OpenAI, and Vercel."
- url: https://agent-plugins.org/
- source_type: primary
- published: unknown (live site as of 2026-09)
- confidence: high

### [6] Agent Skills specification hard-constrains SKILL.md frontmatter — required `name` (1–64 chars, lowercase alphanumeric + hyphens, must match parent directory) and `description` (1–1024 chars); progressive disclosure budget is ~100 tokens for metadata at startup, <5000 tokens for SKILL.md body on activation, and scripts/references/assets only when needed; `allowed-tools` is experimental.
- quote: "Progressive disclosure... Metadata (~100 tokens): The name and description fields are loaded at startup... Instructions (< 5000 tokens recommended): The full SKILL.md body is loaded when the skill is activated... Resources (as needed)."
- url: https://agentskills.io/specification
- source_type: primary
- published: unknown (live spec as of 2026-09)
- confidence: high

### [7] Cursor plugins package rules, skills, agents, commands, MCP servers, and hooks; Cursor supports both the portable Agent Plugins standard (`plugin.json` at root, skills + MCP) and Cursor Plugins (`.cursor-plugin/plugin.json`, adds rules/agents/commands/hooks/variables), distributed via a manually reviewed Cursor Marketplace and Team Marketplaces with install modes Default Off / Default On / Required.
- quote: "Plugins package rules, skills, agents, commands, MCP servers, and hooks into distributable bundles... Teams plan: up to 1 team marketplace; Enterprise plan: unlimited team marketplaces."
- url: https://cursor.com/docs/plugins
- source_type: primary
- published: unknown (live docs as of 2026-09)
- confidence: high

### [8] Cursor rules use `.cursor/rules/*.mdc` with four activation modes driven by frontmatter (`alwaysApply`, `description`, `globs`) plus AGENTS.md (project root + nested subdirs); Team Rules precedence is Team → Project → User, and rules do not affect Cursor Tab or Inline Edit (Cmd/Ctrl+K).
- quote: "Rules provide persistent, reusable context at the prompt level... Rules are applied in this order: Team Rules → Project Rules → User Rules."
- url: https://cursor.com/docs/context/rules
- source_type: primary
- published: unknown (live docs as of 2026-09)
- confidence: high

### [9] Cursor MCP supports stdio / SSE / Streamable HTTP, MCP capabilities including Roots, Elicitation, and the MCP Apps extension (interactive UI returned by tools); config lives in project `.cursor/mcp.json` or global `~/.cursor/mcp.json`, with `${env:}` interpolation, OAuth (static client credentials or DCR), enterprise MCP Allowlist, and programmatic registration via `vscode.cursor.mcp.registerServer()`.
- quote: "Cursor supports these MCP protocol capabilities and extensions: Tools, Prompts, Resources, Roots, Elicitation, Apps (extension)... MCP tools can return interactive UI along with standard tool output."
- url: https://cursor.com/docs/context/mcp
- source_type: primary
- published: unknown (live docs as of 2026-09)
- confidence: high

### [10] OpenCode plugins are JavaScript/TypeScript modules (local `.opencode/plugins/` or npm via Bun auto-install into `~/.cache/opencode/node_modules/`) that return hook objects covering tool.execute.before/after, permission.asked/replied, session.*, file.*, shell.env, tui.*, and can inject custom tools via `tool()`; load order is global config → project config → global plugins → project plugins; experimental `session.compacting` can rewrite compaction prompts.
- quote: "Plugins allow you to extend OpenCode by hooking into various events and customizing behavior... npm plugins are installed automatically using Bun at startup."
- url: https://opencode.ai/docs/plugins/
- source_type: primary
- published: 2026-09-18 (page footer Last updated)
- confidence: high

### [11] OpenCode Agent Skills discovery is deliberately cross-tool: it loads SKILL.md from `.opencode/skills/`, `~/.config/opencode/skills/`, plus Claude-compatible `.claude/skills/` and agent-compatible `.agents/skills/` (project and global), exposes skills via a native `skill` tool description, and enforces pattern-based permissions (`allow`/`deny`/`ask`) per skill name, overridable per agent.
- quote: "OpenCode searches these locations: Project config: `.opencode/skills/<name>/SKILL.md`... Project Claude-compatible: `.claude/skills/<name>/SKILL.md`... Project agent-compatible: `.agents/skills/<name>/SKILL.md`."
- url: https://opencode.ai/docs/skills/
- source_type: primary
- published: 2026-09-18 (page footer Last updated)
- confidence: high

### [12] OpenCode MCP is configured in opencode.json under `mcp` with `type: local|remote`, OAuth via RFC 7591 Dynamic Client Registration (tokens stored at `~/.local/share/opencode/mcp-auth.json`), organization defaults via `.well-known/opencode`, and per-agent tool gating using glob patterns after globally disabling MCP tools.
- quote: "OpenCode automatically handles OAuth authentication for remote MCP servers... Use Dynamic Client Registration (RFC 7591) if supported by the server... Organizations can provide default MCP servers via their `.well-known/opencode` endpoint."
- url: https://opencode.ai/docs/mcp-servers/
- source_type: primary
- published: 2026-09-18 (page footer Last updated)
- confidence: high

### [13] Cline treats extension as five layers: Rules (`.clinerules/` or `.cline/rules/`, also auto-detects `.cursorrules`, `.windsurfrules`, AGENTS.md; conditional activation via YAML `paths` globs), Skills (progressive loading ~100 tokens metadata / <5k tokens SKILL.md body, paths `.cline/skills/`, `.clinerules/skills/`, `.claude/skills/`), MCP (`~/.cline/mcp.json` / IDE settings; STDIO or Streamable HTTP), Plugins (SDK/CLI/Kanban only — TypeScript AgentPlugin from URL/git/npm/local; not yet on VS Code/JetBrains extensions), and Hooks (documented under SDK Plugins).
- quote: "Cline recognizes rules from multiple sources... Cline Rules, Cursor Rules (.cursorrules), Windsurf Rules (.windsurfrules), AGENTS.md... Plugins... currently only applies to Cline SDK, CLI, and Kanban."
- url: https://docs.cline.bot/customization/cline-rules.md
- source_type: primary
- published: unknown (live docs as of 2026-09)
- confidence: high

### [14] Windsurf/Devin Desktop separates auto-generated Memories (local `~/.codeium/windsurf/memories/`, workspace-scoped, legacy Cascade only — Devin Local does not persist them) from durable customization: Rules with four trigger modes (`always_on`, `glob`, `model_decision`, `manual`) at global (6k chars) / workspace `.devin/rules/*.md` (12k chars) / system enterprise paths, plus Skills on agentskills.io progressive disclosure at `.windsurf/skills/` and enterprise OS paths; docs explicitly recommend Rules/AGENTS.md over Memories for knowledge that must be reused.
- quote: "For knowledge you want Cascade to reliably reuse, write it as a Rule or add it to AGENTS.md... Memories apply to the legacy Cascade agent only. The Devin Local agent... does not persist memories."
- url: https://docs.devin.ai/desktop/cascade/memories
- source_type: primary
- published: unknown (live docs as of 2026-09)
- confidence: high

### [15] Continue injects rules into the system message for Agent/Chat/Edit modes via `.continue/rules/*.md` (or YAML) with frontmatter `name`, `globs`, `regex`, `description`, `alwaysApply`; rules are not used in autocomplete/apply, load in lexicographical order, and Agent mode can auto-create rules via the `create_rule_block` tool.
- quote: "Rules are used to provide system message instructions to the model for Agent mode, Chat mode, and Edit mode requests... Rules are not included in autocomplete or apply."
- url: https://docs.continue.dev/customize/deep-dives/rules
- source_type: primary
- published: unknown (live docs as of 2026-09)
- confidence: high

### [16] Aider has no plugin/hooks/skills/marketplace system; the documented extension path is a plain CONVENTIONS.md loaded read-only via `/read CONVENTIONS.md` or `.aider.conf.yml` `read:`, with community conventions in github.com/Aider-AI/conventions — a useful thin baseline showing that conventions files alone are not a near-native plugin layer.
- quote: "The easiest way to do that with aider is to simply create a small markdown file and include it in the chat... You can also configure aider to always load your conventions file in the `.aider.conf.yml` config file."
- url: https://aider.chat/docs/usage/conventions.html
- source_type: primary
- published: unknown (live docs as of 2026-09)
- confidence: high

### [17] Converging industry definition of a near-native plugin capability layer as of 2026-09 is a six-part surface: (1) MCP as the external-tool standard (stdio + HTTP + OAuth), (2) SKILL.md / Agent Skills progressive disclosure with ~100-token always-on metadata, (3) Rules/AGENTS.md with multi-mode activation (always / glob / model-decision / manual), (4) lifecycle hooks with decision control (Pre/PostToolUse, session start/stop, compaction), (5) a packaged plugin unit that bundles the above with a manifest + marketplace/team distribution, and (6) cross-tool path discovery (`.claude/`, `.agents/`, `AGENTS.md`, `.cursor/`, `.opencode/`) so portable components load without re-authoring.
- quote: "Agent Plugins defines a small interoperability floor for the parts that can be portable across clients. Shared components can use one predictable structure, while distribution, installation, permissions, user experience, and client-specific capabilities remain under each client's control."
- url: https://agent-plugins.org/
- source_type: primary
- published: unknown (live site as of 2026-09)
- confidence: medium
