# F1: Supermemory 产品形态与 Memory API 架构

## Findings

### [1] Supermemory positions itself as multi-door "context infrastructure for AI agents," not a single memory API: managed cloud + plugins/MCP + self-hosted binary share one memory store behind the same engine.
- quote: "Context infrastructure for AI agents. Use it with the API, your tools, your team, or run it yourself." / "Every door, one store — API, MCP, plugins, SMFS, and connectors share the same memories"
- url: https://supermemory.ai/docs/overview/what-is-supermemory
- source_type: primary
- published: unknown (docs live as of 2026-09-19)
- confidence: high

### [2] Official Chinese README frames Supermemory as a research team product that wins LongMemEval / LoCoMo / ConvoMem and ships open-source coding-agent plugins that are "implementations of the Supermemory API," not a separate memory backend.
- quote: "Supermemory 是为 AI 设计的记忆与上下文层。在 LongMemEval、LoCoMo 和 ConvoMem 这三大 AI 记忆基准上均位列第一。… 这些插件本质上是 supermemory API 的实现，全部开源"
- url: https://github.com/supermemoryai/supermemory/blob/main/README.zh-CN.md
- source_type: primary
- published: unknown (repo main branch; README.zh-CN.md size 12697, fetched 2026-09-19)
- confidence: high

### [3] Canonical Memory API surface is small and versioned: Bearer `sm_…` auth; writes `POST /v3/documents`; recall `POST /v4/search`; always-on profile `POST /v4/profile`; settings `PATCH /v3/settings`; scoping always `containerTag` (singular) in JSON body — integration prompts explicitly ban `/v3/memories`, `/v3/search` as write/search endpoints and plural `containerTags` / `x-supermemory-api-key`.
- quote: "CANONICAL API SURFACE (use these, nothing else): Auth header: Authorization: Bearer $SUPERMEMORY_API_KEY … Write content: POST https://api.supermemory.ai/v3/documents … Search: POST https://api.supermemory.ai/v4/search … Profile + search: POST https://api.supermemory.ai/v4/profile … Scoping: containerTag (singular string) in the JSON body — never in a header"
- url: https://supermemory.ai/docs/agents-and-mcp
- source_type: primary
- published: unknown (docs live as of 2026-09-19)
- confidence: high

### [4] Core architecture is a dual engine: a custom learning model decides what to learn/forget/relationize, while a Temporal Vector-graph engine (Vector + FTS + graph) stores facts; clients never pre-chunk or pick embeddings.
- quote: "At it's core, supermemory is powered by a custom learning model and a graph database that we built internally." / "Learning model: Decides what and how to learn, what is important, when to forget… Temporal Vector-graph engine: … Fact-based temporal graph that has Vector, FTS, and graph built in."
- url: https://supermemory.ai/docs/concepts/how-it-works
- source_type: primary
- published: unknown (docs live as of 2026-09-19)
- confidence: high

### [5] Ingest pipeline data model produces three outputs under one `containerTag`: document chunks (SuperRAG grounding), graph memories (extracted facts), and entity profiles (static + dynamic summary); pipeline statuses are queued → extracting → chunking → embedding → indexing → done.
- quote: "After the pipeline runs, the same document leads to three things -> Chunks, Memories and Profile. (in the same containerTag)" / "Document status done means chunks are indexed for search. Memories — the graph facts, updates, and derives — come from a second phase called dreaming."
- url: https://supermemory.ai/docs/concepts/how-it-works
- source_type: primary
- published: unknown (docs live as of 2026-09-19)
- confidence: high

### [6] Memory graph uses three explicit relation types — `updates` (temporal replacement with `isLatest`), `extends` (enrichment), `derives` (inference) — plus types Facts / Preferences / Episodes and automatic forgetting (time-based, contradiction, noise); integrators do not hand-maintain the graph.
- quote: "When content is processed, new facts connect to existing ones through three relationship types." / "Updates — information changes … Extends — information enriches … Derives — information infers" / "You do not hand-maintain the graph."
- url: https://supermemory.ai/docs/concepts/graph-memory
- source_type: primary
- published: unknown (docs live as of 2026-09-19)
- confidence: high

### [7] `dreaming` is a load-bearing processing contract for agent plugins: default `"dynamic"` groups related docs for higher graph quality (memories may appear after status `done`); `"instant"` dreams each doc alone, bills one extra operation, and is the documented pattern when the next step must search memories immediately.
- quote: "dynamic (Default? Yes) … Related documents are grouped so memories form from coherent units … Memory extraction may continue after status: \"done\"." / "instant (Default? No) … Bills one extra operation per document."
- url: https://supermemory.ai/docs/concepts/how-it-works
- source_type: primary
- published: unknown (docs live as of 2026-09-19)
- confidence: high

### [8] Multi-tenancy contract: `containerTag` is a hard isolation boundary (auto-creating "spaces"), not soft metadata; naming `^[a-zA-Z0-9_:-]+$` max 100 chars; plural `containerTags` is deprecated and `/v4` only accepts singular; out-of-scope tags return `403 Forbidden`; scoped keys are mintable per container (`POST /v3/auth/scoped-key`) and cannot cross containers or touch billing.
- quote: "A container tag is a hard boundary — its own namespace. Memories in one tag are never returned by a search scoped to another tag." / "Requesting a tag outside the allowed set returns 403 Forbidden." / "The plural containerTags array field is deprecated… The /v4 API only accepts containerTag."
- url: https://supermemory.ai/docs/concepts/container-tags
- source_type: primary
- published: unknown (docs live as of 2026-09-19); scoped-key example `expiresAt` includes 2026-03-08
- confidence: high

### [9] Recall contract for agents: `POST /v4/search` with `searchMode` in {`memories`,`documents`,`hybrid` (recommended)}, `include.relatedMemories` for graph edges, `include.forgottenMemories` opt-in; hybrid results carry either `memory` or `chunk`. Profiles via `POST /v4/profile` return `profile.static` + `profile.dynamic` (plus optional topic `buckets`); docs claim profiles need 1 call / 50–100ms vs 3–5 search queries / 200–500ms for pure-search context assembly.
- quote: "Prefer v4 with searchMode: \"hybrid\" unless you only need document chunks or only extracted memories." / "In hybrid mode, results contain either a memory field (extracted facts) or a chunk field (document content)" / "Context retrieval: 3-5 queries → 1 call; Response time: 200-500ms → 50-100ms"
- url: https://supermemory.ai/docs/recall/search
- source_type: primary
- published: unknown (docs live as of 2026-09-19)
- confidence: high

### [10] OpenCode plugin agent contract (opencode-supermemory): install via `bunx opencode-supermemory@latest install`; registers in `~/.config/opencode/opencode.jsonc` as `"plugin": ["opencode-supermemory"]`; exposes one `supermemory` tool with modes `add|search|profile|list|forget`; scopes `user` vs `project` (default) mapped onto container tags via `sm_scope` metadata and `repo_{project}__{hash}` tags; features include session-start context injection, keyword auto-save, 80% compaction, and `<private>` redaction.
- quote: "OpenCode sends the same shared coding-agent entity context as Claude Code and Codex. Personal and project memories are distinguished with sm_scope metadata inside the shared repository container." / "Modes: add, search, profile, list, forget" / "compactionThreshold: 0.80"
- url: https://github.com/supermemoryai/opencode-supermemory (README via GitHub API) and https://supermemory.ai/docs/integrations/opencode
- source_type: primary
- published: unknown (repo main; README.md size 9232, GitHub API fetched 2026-09-19)
- confidence: high

### [11] Claude Code plugin agent contract: Claude marketplace install `/plugin marketplace add supermemoryai/claude-supermemory` + `/plugin install supermemory`; Node 18+ hooks; env `SUPERMEMORY_CC_API_KEY`; behaviors = reasoned recall before turns, auto-capture of conversations/tool usage, separate team vs personal containers, slash commands `/supermemory:index|project-config|session|status`; project config `.claude/.supermemory-claude/config.json` can override `baseUrl`, `repoContainerTag`, `personalContainerTag` for self-host.
- quote: "Reasoned recall — Before each turn, Claude decides whether recalling memory would help the current message, and only searches when it is worth it." / "Team memory — Project knowledge is shared separately from personal memories." / "\"baseUrl\": \"https://api.supermemory.ai\" … \"repoContainerTag\": \"my-team-project\""
- url: https://supermemory.ai/docs/integrations/claude-code
- source_type: primary
- published: unknown (docs live as of 2026-09-19)
- confidence: high

### [12] Supermemory MCP is a remote OAuth MCP server at `https://mcp.supermemory.ai/mcp` with a fixed agent tool surface (`search_memory`, `get_profile`, `add_memory` with save/forget, `list_documents`, `get_document`, `list_memories`, `list_spaces`, `who_am_i`), MCP Apps widgets (`select-space`, `guided-save`, `upload-file`, `memory-graph`), resources `supermemory://profile` / `supermemory://spaces`, and a `context` prompt; source lives under monorepo `apps/mcp`.
- quote: "Add this remote MCP server to any compatible client: https://mcp.supermemory.ai/mcp" / "Supermemory uses OAuth, so no API key is required." / Tool table: search_memory, get_profile, add_memory, list_documents, get_document, list_memories, list_spaces, who_am_i
- url: https://supermemory.ai/docs/supermemory-mcp/mcp
- source_type: primary
- published: unknown (docs live as of 2026-09-19)
- confidence: high

### [13] SMFS is Supermemory's filesystem-shaped extension point for coding agents: mounts a container as a real directory (NFSv3 macOS / FUSE Linux) with semantic `grep` by default, distilled memory paths, virtual `profile.md`, bidirectional sync; serverless agents get `@supermemory/bash` / `supermemory-bash` virtual bash instead of a mount; docs explicitly pitch "Memory your agent can grep" so agents need no SDK.
- quote: "SMFS mounts your Supermemory container as a real directory. Agents read it with ls, cat, and grep. No SDK to learn, no client to wire up, no embeddings to think about." / "Semantic grep by default… Virtual profile.md… Bidirectional sync runs in the background."
- url: https://supermemory.ai/docs/smfs/overview
- source_type: primary
- published: unknown (docs live as of 2026-09-19)
- confidence: high

### [14] Self-hosted product form is a single zero-config binary (`npx supermemory local` or `curl -fsSL https://supermemory.ai/install | bash`) that embeds the graph engine + local embeddings (default `Xenova/bge-base-en-v1.5` 768d) + full Memory API (`/v3/documents`, `/v4/search`, `/v4/profile`), speaks the same API as cloud via `baseURL` (default local port 6767), and accepts any OpenAI-compatible LLM (incl. offline Ollama); connectors and hosted MCP are platform-only; coding plugins can target local via `SUPERMEMORY_API_URL` / plugin `baseUrl`.
- quote: "Supermemory runs on your own hardware. It's the same memory engine behind the hosted platform — … as a single self-contained binary." / "The self-hosted server speaks the same API as the hosted platform. Point any Supermemory SDK at it with a one-line change" / "self-hosted plugins all target your local server with SUPERMEMORY_API_URL=http://localhost:6767"
- url: https://supermemory.ai/docs/self-hosting/overview
- source_type: primary
- published: unknown (docs live as of 2026-09-19)
- confidence: high

### [15] Developer/agent scaffolding layer for coding agents (distinct from consumer Memory MCP) is CLI + skill + docs MCP: `npx supermemory setup|help --json`, skill from `github.com/supermemoryai/skills`, docs MCP at `https://supermemory.ai/docs/mcp`; monorepo top-level includes `apps/`, `packages/`, `skills/` alongside README.zh-CN.md; official SDKs are npm/pypi package `supermemory` with `client.add/search/profile/documents/settings`.
- quote: "Best combo for coding agents: skill + docs MCP + npx supermemory setup." / monorepo listing includes apps, packages, skills, README.zh-CN.md / "Both SDKs also work against self-hosted Supermemory — pass baseURL: \"http://localhost:6767\""
- url: https://supermemory.ai/docs/agents-and-mcp and https://api.github.com/repos/supermemoryai/supermemory/contents/
- source_type: primary
- published: unknown (docs + GitHub API fetched 2026-09-19)
- confidence: high

### [16] Ingest knobs that matter for plugin architecture: `customId` enables conversation/document identity + diff billing on re-ingest; `taskType: "memory"` (default) extracts facts/profile/graph while `taskType: "superrag"` only chunk/embed/index at documented 5x cheaper per token; `entityContext` (≤1500 chars, per container) and org `filterPrompt`/`shouldLLMFilter`/`chunkSize` customize extraction; file upload max 50MB; OpenAPI 3.1 live at api.supermemory.ai with bearerAuth and info.version "3.0.0".
- quote: "taskType: \"superrag\" — chunks/embeds for search only. No fact extraction, no profile updates. Priced at 5x cheaper per token than \"memory\"." / "Use a stable customId when the same conversation or file will be updated later… drives diff billing" / OpenAPI info: "title":"supermemory API","version":"3.0.0"
- url: https://supermemory.ai/docs/ingestion/add-memories and https://api.supermemory.ai/v4/openapi
- source_type: primary
- published: unknown (docs + OpenAPI live as of 2026-09-19)
- confidence: high
